## 1. Architecture Overview

This system employs a multi-agent architecture to autonomously probe GPU hardware characteristics through LLM-generated CUDA micro-benchmarks.

### Agent Pipeline

### Key Design Decisions

1. **No Static Benchmarks**: All CUDA code is autonomously generated by the LLM at runtime based on measurement methodology knowledge embedded in prompts. No pre-built `.cu` templates are included — compliant with the "no hardcoded benchmarks" requirement.

2. **Anti-Tampering**: The system does NOT trust `cudaGetDeviceProperties` or `nvidia-smi` reported values. Instead, it:
   - Measures actual clock frequency via FMA instruction timing
   - Detects frequency locking by comparing measured vs reported clocks
   - Uses pointer chasing to bypass prefetchers for accurate latency measurement
   - Validates results against physical consistency constraints (L1 < L2 < DRAM)

3. **Iterative Self-Correction**: Each metric gets up to 3 attempts. If code fails to compile or produces out-of-bounds results, the error is fed back to the LLM for improved code generation.

4. **Physical Consistency Validation**: Post-measurement cross-checks ensure:
   - Latency hierarchy: L1 < L2 < DRAM
   - Bandwidth within theoretical limits
   - Cache sizes are power-of-2 multiples
   - Clock frequency consistent with bandwidth observations

## 2. Measurement Methodologies

| Metric | Method |
|:---|:---|
| Memory Latency (L1/L2/DRAM) | Pointer chasing with random permutation chains at different array sizes |
| Cache Size Detection | Logarithmic sweep of latency vs array size, cliff detection |
| Global Memory Bandwidth | Streaming float4 copy/read kernels, CUDA event timing |
| Shared Memory Bandwidth | Conflict-free access pattern across all SMs |
| Clock Frequency | FMA instruction count with dual timing (clock64 + CUDA events) |
| Bank Conflict Penalty | Differential measurement: conflict-free vs all-same-bank |
| Shared Memory Capacity | Linear scan with cudaFuncSetAttribute for extended shmem |

## 3. Innovation Points

1. **Environment Fingerprint Detection**: Compares LLM-probed values against API-reported values to detect tampering (frequency locking, SM masking)
2. **Physical Consistency Validator**: 6 cross-checks ensure measured values are mutually consistent
3. **NCU Bottleneck Analyzer**: Roofline-based classification (Compute/Memory/Latency bound) from ncu metrics
4. **Resilient LLM Client**: Automatic retry with exponential backoff, raw response parsing for relay API compatibility

## 4. Technology Stack

- **LLM**: OpenAI-compatible API (GPT-5.4 in eval, Sonnet 4.5 in dev)
- **Language**: Python 3.11+ with subprocess-based CUDA compilation
- **CUDA**: nvcc compilation with auto-detected GPU architecture
- **No external benchmark dependencies**
